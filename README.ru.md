# RagDocAgent

RagDocAgent — разворачиваемое локально рабочее пространство для вопросов по
PDF, DOCX и электронным таблицам. В одном компактном интерфейсе объединены
поиск, просмотр документов и ответы со ссылками на источники.

## Обзор

Добавьте документы, выберите модель и ищите информацию или задавайте вопросы
на русском и английском языках. Ссылки в ответах открывают соответствующие
фрагменты в просмотрщике. Приложение поддерживает локальные эмбеддинги и
демо-модель, а также подключение внешних провайдеров языковых моделей.

## Возможности

- Загрузка и индексация PDF, DOCX, XLSX и XLS.
- Чат с поиском по документам и многошаговый режим агента.
- Прямой поиск фрагментов без вызова языковой модели.
- Гибридный поиск: векторное сходство и BM25.
- Просмотр источников в PDF, Word и таблицах.
- История диалогов, категории, английский и русский интерфейс.
- Потоковая выдача и голосовой ввод браузера.

## Архитектура

Клиент на React обращается к FastAPI через существующие маршруты `/api`.
Сервис разбирает загруженные файлы, формирует фрагменты и эмбеддинги, хранит
метаданные документов и диалоги в SQLite. Векторы хранятся в ChromaDB.
Гибридный поиск объединяет результаты векторного поиска и BM25 с помощью
reciprocal rank fusion. Ответы чата и агента передаются клиенту потоком вместе
со ссылками на источники.

## Технологии

- **Клиент:** React, TypeScript, Vite
- **API:** Python, FastAPI
- **Хранение:** SQLite и ChromaDB
- **Поиск:** локальные или OpenAI-эмбеддинги, BM25, reciprocal rank fusion
- **Модели:** OpenAI, Anthropic, Z.ai, Ollama и автономный mock-режим
- **Развёртывание:** Docker и Docker Compose

## Установка

Требуются Python 3.12+, Node.js 22+ и npm. Docker необязателен.

```powershell
git clone <адрес-вашего-репозитория> RagDocAgent
cd RagDocAgent
python -m venv backend\.venv
backend\.venv\Scripts\Activate.ps1
pip install -r backend\requirements.txt
cd frontend
npm ci
```

В macOS или Linux из корня репозитория активируйте окружение командой
`source backend/.venv/bin/activate`.

## Настройка

Скопируйте `backend/.env.example` в `backend/.env`. Ключи провайдеров
необязательны: без них доступны локальные эмбеддинги и автономная mock-модель.

| Переменная | Назначение |
| --- | --- |
| `OPENAI_API_KEY` | Доступ к моделям или эмбеддингам OpenAI |
| `ANTHROPIC_API_KEY` | Доступ к моделям Anthropic |
| `ZAI_API_KEY` | Доступ к моделям Z.ai |
| `OLLAMA_BASE_URL` | Адрес сервера Ollama |
| `EMBEDDING_PROVIDER` | `local` (по умолчанию) или `openai` |
| `SEARCH_HYBRID` | Включение объединения BM25 и векторного поиска |
| `SEARCH_RERANK` | Необязательное ранжирование cross-encoder |

Для аналитики задайте `VITE_YANDEX_METRIKA_ID` или
`VITE_GA4_MEASUREMENT_ID` при сборке клиента. Значения `VITE_*` попадают в
клиентский bundle; не храните в них секреты.

## Локальный запуск

Запустите API из корня репозитория:

```powershell
cd backend
uvicorn app.main:app --reload --port 8000
```

В другом терминале запустите клиент:

```powershell
cd frontend
npm run dev
```

Откройте адрес Vite из терминала (обычно `http://localhost:5173`). API доступен
на `http://localhost:8000`, интерактивная документация — по пути `/docs`.

## Развёртывание в Docker

Для запуска отдельных сервисов с сохранением локальных данных:

```powershell
docker compose up --build
```

Клиент будет доступен на порту 5173, API — на порту 8000. Единый образ,
обслуживающий API и собранный клиент:

```powershell
docker build -t ragdocagent .
docker run --rm -p 7860:7860 -v ragdocagent-data:/app/data ragdocagent
```

Единый образ учитывает переменную окружения `PORT`. Файл `render.yaml` можно
использовать как основу конфигурации для Render. Ключи провайдеров задавайте
в хранилище секретов платформы.

## Безопасность

Храните ключи провайдеров в переменных окружения или в хранилище секретов
платформы, а не в репозитории и не в клиентском bundle. Загруженные файлы и
диалоги сохраняются на сервере. В API нет встроенной аутентификации; перед
публикацией для недоверенных пользователей ограничьте сетевой доступ или
добавьте внешний слой контроля доступа. Для постоянного окружения создавайте
резервные копии тома `/app/data`.
